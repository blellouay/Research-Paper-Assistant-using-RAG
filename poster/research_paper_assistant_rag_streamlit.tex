\begin{posterbox}{Abstract and objective}
Researchers must locate evidence across long, structured papers. General-purpose
language models can answer from outside knowledge or introduce unsupported claims.

\textbf{Objective:} answer single-paper and cross-paper questions using only
retrieved evidence, with citations and claim-level filtering before synthesis.

\begin{itemize}
  \item Ingest multiple scientific PDFs.
  \item Preserve text, tables, figures, equations, references, and provenance.
  \item Retrieve and rerank relevant passages.
  \item Compare evidence across named papers and requested aspects.
  \item Answer questions from both text and cropped paper figures.
  \item Remove claims not supported by retrieved excerpts.
\end{itemize}
\end{posterbox}

\begin{posterbox}{Scientific PDF ingestion}
\textbf{GROBID} converts PDFs into structured TEI/XML. The parser retains title,
authors, abstract, sections, paragraphs, tables, formulas, bibliography entries,
figure captions, and PDF crop coordinates.

\begin{center}
\begin{tikzpicture}[node distance=1.1cm]
  \node[verify] (a) {Scientific PDF};
  \node[verify,right=of a] (b) {GROBID};
  \node[verify,right=of b] (c) {Typed Evidence};
  \draw[flow] (a)--(b); \draw[flow] (b)--(c);

\end{center}

\textbf{PyMuPDF} uses GROBID coordinates to crop retrieved figures from the
original PDF. The same image is displayed with the answer and sent to Groq's
vision-capable model for grounded visual interpretation.
\end{posterbox}

\begin{posterbox}{Section-aware semantic indexing}
Each chunk retains:
\begin{itemize}
  \item paper title and document name,
  \item section name and chunk ID,
  \item evidence type, label, and caption,
  \item figure crop coordinates when available.
\end{itemize}

\begin{posterbox}{Multi-paper comparison}
Naive global search can over-represent one paper. Broad comparison questions are
decomposed into objectives, methods, datasets, results, limitations, and
contributions. Each aspect is retrieved independently for every selected paper.

\textbf{Routing signals:} paper filters, aspect decomposition, balanced evidence,
atomic claims, entity detection, primary-subject identification, and
claim-specific retrieval. Dataset and result searches retrieve extra passages
to recover named benchmarks and numerical metrics.
\end{posterbox}

\begin{posterbox}{Verification example}
\textbf{Rejected draft claim}\par
\begin{tcolorbox}[colback=PosterRed!6,colframe=PosterRed,arc=3mm]
``The original Transformer uses constrained self-attention.''
\end{tcolorbox}
The evidence describes masking in the decoder; it does not establish that the
entire architecture uses constrained self-attention. \textbf{Removed.}

\vspace{3mm}
\textbf{Supported claim}\par
\begin{tcolorbox}[colback=PosterCyan!7,colframe=PosterCyan,arc=3mm]
``BERT uses bidirectional self-attention.''
\end{tcolorbox}
Explicitly supported by the BERT model-architecture evidence. \textbf{Retained.}
\end{posterbox}

\begin{posterbox}{Grounded comparison example}
\textbf{Question:} Compare BERT with the original Transformer architecture.

\textbf{BERT}
\begin{itemize}
  \item Multi-layer bidirectional Transformer encoder.
  \item Uses bidirectional self-attention.
  \item Unified architecture across tasks.
\end{itemize}

\textbf{Original Transformer}
\begin{itemize}
  \item Attention-based sequence-transduction model.
  \item Encoder-decoder architecture.
\end{itemize}

\textbf{Key difference:} BERT is encoder-based; the original Transformer has
both encoder and decoder components.

\begin{posterbox}{Evaluation framework implemented}
The repository includes deterministic unit tests and a reusable end-to-end
evaluation framework. No completed benchmark run is stored in
\texttt{evaluation/results/}, so the poster does not invent performance scores.

\textbf{Retrieval evaluation}
\begin{itemize}
  \item Hit@1, Hit@3, Hit@5, and mean reciprocal rank.
  \item Vector retrieval before vs. after reranking.
  \item Paper and section matching.
  \item Comparison-paper coverage.
\end{itemize}

\textbf{Grounding evaluation}
\begin{itemize}
  \item Fully, partially, and unsupported claim rates.
  \item Citation validity and rejected-claim leakage.
  \item Expected-fact coverage and abstention accuracy.
\end{itemize}

\end{posterbox}

\begin{posterbox}{Implemented contributions}
\begin{itemize}
  \item Structure-aware scientific PDF ingestion.
  \item Typed indexing of paragraphs, tables, equations, figures, and references.
  \item Coordinate-based figure cropping and multimodal Groq inference.
  \item Dense retrieval plus cross-encoder reranking.
  \item Aspect-balanced, paper-aware multi-paper evidence routing.
  \item Atomic claim extraction and source-scope verification.
  \item Citation-grounded synthesis, safe re-index replacement, and evaluation.
\end{itemize}
\end{posterbox}

\begin{posterbox}{Perspectives}
\begin{itemize}
  \item Groq sends selected excerpts and figure crops to a cloud service.
  \item Figures without GROBID coordinates remain caption-only evidence.
  \item Dense retrieval can miss highly specific technical evidence.
  \item Verified mode increases API calls and inference time.
  \item Next: hybrid retrieval, visual-table OCR, and a larger benchmark run.
\end{itemize}
\end{posterbox}

\begin{posterbox}{Conclusion}
\color{ReferenceOrange}
The system combines typed scientific-document processing, balanced multi-paper
retrieval, visual figure understanding, cloud or local generation, citations,
and claim-level verification to answer from evidence researchers can inspect.
\color{black}
\end{posterbox}
